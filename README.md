### 최근 변경 — v0.28.0 → v0.29.0

로드맵이 "남은 진짜 과제"로 남겨 둔 **도메인 지식 연결**이 이번 릴리스다 — 고정하면 전문
에이전트가 이어받는다는 설계가, 이제 사용자의 자료까지 읽는 전문가로 완성된다. 모델이 무엇을
해석하든 **발췌는 지시가 아니라 데이터**이고, 계획의 숫자는 여전히 계획 도구가 소유한다.
전체 이력은 [CHANGELOG.md](CHANGELOG.md), 실측 수치는
[docs/QA_RESULT_v0.25.0.md](docs/QA_RESULT_v0.25.0.md)(직전 릴리스 게이트) 참고.

AI 코치와의 대화로 하루 단위 계획(체크리스트)을 만들고 → 오늘 할 일을 실행하고 → "오늘 마무리" 회고로 하루를 닫습니다.
코치는 v0.15.0부터 **도구를 호출하는 에이전트**입니다 — 완료율·회고 같은 사실을 추측하지 않고 서버 도구로 확인하고, 계획 수정도 도구로 실행합니다.
최종 목표는 **계획을 고정하는 순간, 체크리스트 완성 도우미 대신 그 목표의 전문 에이전트가 이어받는 것**입니다 —
v0.17.0에서 그 1단계에 도달했습니다: 계획을 고정하면 **목표명으로 특화된 전문 에이전트 프로필**(시스템 프롬프트 + 도구 집합)이 대화를 이어받습니다.

## 핵심 기능

- **슬롯필링 대화 → 계획 생성** — 목표·기간·시간·수준을 묻고 하루 단위 투두리스트 초안을 생성(SSE 실시간 스트리밍, API 키 없으면 mock 폴백).
- **자유 대화로 계획 보완 + 상태 수명주기** — 수정 요청·질문을 LLM이 구분해 처리하고, "고정" 버튼으로 확정하면 수정 없이 실행에 집중. 계획은 `초안(DRAFT) → 고정(CONFIRMED) → 완료(COMPLETED)`(또는 중단)의 서버 전이표를 따르며, 상태를 다루는 버튼(고정·기간 연장·중단·다시 만들기)은 체크리스트 탭의 **계획 동작 바**에 있습니다(대화창에는 상태 안내 칩만).
- **여러 계획 보관 + 오늘 할 일** — 계획은 서버 보관함에 자동 저장되고, **오늘 탭**에 모든 계획의 오늘 항목이 모입니다. 배포 환경(`postgres` 프로필)은 PostgreSQL에 영속되어 서버 재시작에도 유지되고, 로컬/단위 테스트 기본값은 인메모리(휘발성)입니다. 계획 생성은 게스트당 **하루 5회**로 제한됩니다(v0.20.0 — 삭제해도 그날의 횟수는 돌아오지 않음).
- **Goal Challenge — 자동으로 열리는 정원 한정 챌린지(v0.21.0 · v0.23.0)** — 챌린지는 사용자가 개설하지 않습니다. 계획을 만들 때 AI가 목표의 **목적 카테고리**를 함께 정해 두고(초안 생성과 같은 호출 — 추가 비용 없음), **비슷한 조건(기간 + 목적)의 체크리스트를 고정한 사람이 3명 모이면** 서버가 그 자리에서 챌린지를 엽니다(예: "어학 14일 챌린지", 정원 5명·참가비 100P). 사용자가 하는 일은 참가뿐입니다. 남은 자리 1개에 여러 명이 **동시에** 요청해도 정확히 한 명만 성공하고, 실패한 사람의 포인트는 차감되지 않습니다 — 정원 검사가 UPDATE의 WHERE 절 안에 있고(조건부 UPDATE), 차감·등록·예약이 한 트랜잭션이기 때문입니다([docs/CONCURRENCY.md](docs/CONCURRENCY.md)).
- **Google 로그인 + 게스트 보관함 흡수(v0.22.0)** — 시작 화면에서 **"Google 계정으로 계속하기"** 또는 **"게스트로 시작하기"**(닉네임 자동 생성)를 고릅니다. 게스트는 브라우저가 생성한 ID로 계획·회고·이력이 격리되어 바로 쓸 수 있고, **Google로 로그인하면 그 브라우저의 게스트 데이터가 계정으로 흡수**되어 어느 기기에서든 같은 보관함이 열립니다. 로그인 전 게스트 보관함은 여전히 브라우저 단위라, 게스트 ID를 잃으면(브라우저 데이터 삭제 등) 로그인 없이는 재연결할 수 없습니다.
- **일일 회고 → 전체 계획 완료 연동** — 자동 계산된 완료율에 체감 난이도·이유를 더해 하루를 마무리하면 해당 Day 카드에 "오늘 마무리 완료" 배지가 붙습니다(오늘 계획 완료). 마무리 시점(종료일 도달 또는 100% 완료)의 회고 저장은 **전체 계획 완료(종결)** 처리를 함께 제안합니다 — 일 단위 마무리와 계획 종결을 구분해 표시.
- **미완료 내일로 이동 + 지난 날짜 잠금** — 오늘 못 끝낸 항목을 버튼 하나로 내일로 이월(종결 전 계획, 고정 후에도 가능). 고정된 계획의 지난 날짜 완료 체크는 소급 변경할 수 없습니다(미루지 않은 지난 항목은 놓친 것으로 확정).
- **계획 변경 이력** — 생성·수정·고정·완료 체크·회고·삭제가 언제, 어느 세션에서 일어났는지 계획별로 조회.
- **다음 계획 분량 추천** — 완료했거나 3일 이상 실행한 계획에서 서버가 수행 기록을 계산하고 규칙으로 다음 하루 분량을 제안합니다(AI는 이유·내용만, 승인 전 미저장). 같은 목표의 최근 계획을 최대 3건 합산해 통계를 안정화합니다.
- **AI 코치의 에이전트화(도구 호출)** — 코치가 답하기 전에 서버 도구를 호출합니다(오늘 할 일·주간 완료율·회고 기록·분량 추천 조회 + 계획 수정·미완료 이월). **어떤 도구를 모델에게 노출할지는 계획 상태(`PlanStatus`)가 결정**하므로, 고정된 계획에는 수정 도구가 프롬프트에 실리지 않습니다 — 프롬프트로 부탁하는 것이 아니라 구조적으로 수정이 불가능합니다. 말풍선 위의 **실행 추적 패널**에서 호출한 도구와 서버가 돌려준 결과를 펼쳐 볼 수 있고, 도구를 지원하지 않는 모델에서는 기존 대화 경로로 자동 폴백합니다.
- **상태별 에이전트 프로필(v0.17.0)** — 상태는 도구만 고르는 것이 아니라 **누가 응대하는지**도 고릅니다: 초안은 체크리스트 완성 코치, 고정하면 **목표명으로 특화된 전문 에이전트**(예: "정보처리기사 실기 전문 에이전트"), 종결(완료/중단)되면 돌아보기와 다음 계획 준비를 돕는 **회고 도우미**. 대화 패널 헤더와 실행 추적 패널에 현재 프로필이 표시됩니다.
- **전문 에이전트의 도메인 지식 — 올린 자료 검색(v0.29.0)** — 계획에 강의 노트·기출 요약 같은 **참고 자료를 붙여넣으면**(체크리스트 탭의 "참고 자료" 블록, 계획당 10개·자료당 20,000자) 서버가 검색용 청크로 나눠 보관하고, **고정한 뒤의 전문 에이전트가 `search_domain_knowledge` 도구로 그 자료에서 근거를 찾아 출처와 함께 답합니다**. 검색은 외부 의존성 없는 렉시컬 방식(문자 bigram)이라 조사·어미가 달라도("정규화를"/"정규화가") 어간이 겹치면 찾습니다. 이 도구는 **초안에는 노출되지 않습니다**(`PlanStatus.allowsDomainResearch()` — 고정이 곧 전문가 인계 전환점, 종결 후에는 회고 도우미가 다음 계획 준비에 참고). 발췌는 데이터일 뿐 지시가 아니며(프롬프트가 명시 + 평가 인젝션 축이 검증), 계획의 숫자는 여전히 계획 도구가 소유합니다.
- **모바일 우선 화면 + 넓은 화면 2분할** — 좁은 폭에서는 한 번에 한 패널(대화 / 오늘 / 체크리스트 / 챌린지)이 세로 전체를 쓰고 **하단 고정 탭바**로 전환합니다. **1024px 이상에서는 화면을 꽉 채워 2분할** — 왼쪽에 대화가 항상 보이고 오른쪽 칸만 같은 탭바로 갈아끼웁니다(대화 ↔ 체크리스트를 동시에 보며 에이전트가 계획을 고치는 걸 실시간으로 확인). 탭을 옮겨도 비활성 패널은 언마운트되지 않아 대화 스크롤과 진행 중인 스트리밍이 유지됩니다.
- **서버 소유 작성·실행·오늘 읽기 모델(v0.19.0)** — 계획 작성의 4단 질문과 검증, 작업 완료 토글, 오늘 화면의 계획·회고 조합을 서버가 처리합니다. 프론트는 메시지·명령을 보내고 서버가 반환한 결과를 표시합니다.

## 빠른 시작

```bash
# 백엔드 (포트 8080)
cd backend && OPENROUTER_API_KEY=<your_key> ./gradlew bootRun

# 프론트엔드 (포트 5173)
cd frontend && npm install && npm run dev
```

또는 단일 컨테이너로:

```bash
docker build -t delaynomore . && docker run -p 8080:8080 -e OPENROUTER_API_KEY=<your_key> delaynomore
```

`OPENROUTER_API_KEY`가 없어도 기동되며 mock 폴백으로 동작합니다. 자세한 내용은 [실행·배포 가이드](docs/DEPLOY.md)를 보세요.
